# 11. Desktop UI

**Goal:** Describe a window with columns, labels, buttons, and real inputs — a form that
stays in sync with your data.

## The `window` block

A UI redraws every frame. Labels with `{counter}` always show the current value — you do
not manually “refresh” the text.

```plaintext
counter = 0

make function called increment() {
    increase counter by 1
}

window "Counter" (width: 420, height: 260) {
    column (padding: 24, spacing: 16, align: center) {
        text "You clicked {counter} times" (size: 26)
        button "More" (on_click: increment)
    }
}
```

## Widgets and properties

| Widget | Role |
|--------|------|
| `column` / `row` | Layout |
| `text` | Label (supports interpolation) |
| `button` | Clickable; use `on_click: some_function` |
| `spacer` | Empty space |
| `text_field` | Typeable text box |
| `checkbox` | On / off |
| `slider` | Number in a range |
| `image` | Show a sprite from `load_sprite` |

Useful properties: `padding`, `spacing`, `align`, `size`, `width`, `height`, `color`,
`bg` (window background), `font`, `sprite`, `on_click`, `bind`, `on_change`, `min` / `max` /
`step` (slider).

## Binding state with `bind:`

Interactive widgets can read and write an ordinary variable:

```plaintext
name = ""
subscribed = false
volume = 50

text_field (bind: name, width: 320)
checkbox "Subscribe" (bind: subscribed)
slider (bind: volume, min: 0, max: 100, step: 1, width: 320)
```

Prefer `bind:` when you just need the latest value. Prefer `on_change:` when you want to
run code the moment it changes (often with an inline function from lesson 5):

```plaintext
text_field (
    value: name,
    on_change: make function (new) { name = new }
)
```
